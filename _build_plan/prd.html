ADS Command Center

A local operations dashboard for managing multiple Claude Code and Codex sessions across projects. Each session tile shows visual identity, a live token gauge, active agent model and spend, and which MCP servers are engaged — so you can see everything running, what it's costing, and what's next, at a glance. Built-in session health alerts nudge you to compact, hand off, or close idle sessions before context rot or token waste sets in. A beads backlog panel lets you launch a new session or load a task into an existing one directly from your backlog.

Built as a Node.js + React local web app served on localhost. Designed with clean config boundaries so it can be productized and distributed to other Claude Code power users. Delivered across 4 milestones.

Node.js React Local web app (localhost) ADS Brand (v1 default) No auth / single user

What the app does

  • Session Tiles

    One color-coded tile per active Claude Code or Codex session, showing project name, agent type, model, and status at a glance.

  • Live Token Gauge

    Per-tile progress bar with threshold markers at 80K, 120K, and 150K tokens — color shifts green to yellow to orange to red as limits approach.

  • Session Health Alerts

    Visual and audible nudges when a session crosses a token threshold or goes idle — with per-tile audio toggle and selectable alert sounds.

  • Agent and MCP Status

    Live agent model, estimated session spend, and MCP server badges (green when active, gray when idle) per tile — plus a summary bar across all sessions.

  • Beads Backlog Panel

    Collapsible sidebar showing open beads items by project with one-click buttons to launch a new session or load a task into an existing tile.

  • Session Launcher

    Opens a new terminal window (iTerm2 or macOS Terminal) in the correct project directory with the agent command pre-typed and registers a new tile instantly.

  • Changelog Feed

    Per-project feed of recent changes.*.md files — preview the first lines, click to expand inline without opening a file.

  • Brain Capture Shortcut

    Persistent one-click capture button that opens a modal to write and send a Brain entry — configurable endpoint, Brain API as the default.

Already provided by the Node.js + React scaffold

  • Local HTTP server (Express)
  • React component system and hot reload
  • File system access (Node.js fs)
  • Shell command execution (child_process)
  • npm package ecosystem
  • No auth / no database needed

Out of scope (v1)

  • Multi-provider support (ChatGPT, Gemini) — tile system is provider-aware by design; wiring additional providers is a v2 task.
  • Mobile or responsive view — this is a desktop command center; mobile layout is not a use case.
  • Cloud sync or remote access — everything runs locally; no server, no accounts, no sync.
  • Team and multi-user features — single operator only in v1; multi-user is a product-tier decision for v2.
  • Full chat transcript viewer — the changelog feed covers session history; deep transcript scrolling is out of scope.
  • Automated session actions — alerts surface prompts; the user always takes the action. No auto-compact, auto-close, or auto-capture.
  • Custom color picker per tile — colors are auto-assigned from a curated palette on project creation.
  • Historical spend analytics and charts — live per-session spend is in scope; aggregated trends and charts are v2.

External integrations

Brain API

Brain Capture Shortcut

A configurable HTTP endpoint the dashboard calls when you hit the Brain Capture button. Defaults to the ADS Open Brain API. Other users point it at their own endpoint via settings. The API key is never stored in the app — it is read from an environment variable at runtime.

Credentials needed

  • CAPTURE_API_KEY — already in arc-secrets.env (ADS default)
  • Brain endpoint URL — configurable in app settings

Local system (no API key)

All other features

Session tiles, token gauges, MCP status, changelog feed, and beads panel all read local files and run shell commands on your Mac. No external API keys required for these features.

Local sources read

  • ~/.claude/projects/ — Claude Code session files
  • bd list — beads CLI (already installed)
  • changes.*.md — per-project changelog files

Foundation + Dashboard Shell

Establishes the project scaffold, wires in ADS brand tokens, and delivers a working dashboard shell with project configuration and an empty tile grid — the visible skeleton everything else snaps into.

What gets built

  • Node.js + React app scaffold, served on localhost
  • ADS brand tokens applied — ads-tokens.css as first stylesheet, zero brand violations
  • Main dashboard layout: header summary bar, tile grid area, collapsible sidebar
  • Project configuration UI — add, edit, and remove projects with name, path, and launch command
  • Settings screen — Alert Config thresholds, Custom Action endpoint, Brand Config mode selector
  • Empty tile grid renders configured projects as placeholder tiles
  • ads-brand-audit passes with zero failures

Not in this milestone

  • Live session data (tiles are empty placeholders)
  • Token gauges, MCP badges, or spend data
  • Alerts, audio, or beads panel
  • Session launcher (terminal spawning)

Done when: The dashboard opens in a browser at localhost, displays the configured projects as placeholder tiles in a color-coded grid, and the settings screen saves and restores project config. ads-brand-audit passes with zero failures.

2

Live Session Monitoring

Brings the tile grid to life by reading Claude Code's local session files and surfacing real-time token counts, model info, spend estimates, and MCP server status on each tile.

What gets built

  • Session detection — discovers active Claude Code sessions by reading ~/.claude/projects/
  • Session tiles display: color bar, project name, agent type, model, status (active/idle/closed)
  • Live token gauge with 80K / 120K / 150K threshold markers and color shift
  • MCP server badges per tile — green when engaged, gray when idle, tooltip with name and last-used time
  • Estimated session spend displayed per tile
  • Dashboard summary bar: X sessions active, Y MCPs engaged, ~$Z spent today
  • Polling interval keeps all data fresh automatically
  • Tiles sorted by most recently active first

Not in this milestone

  • Alerts or audio nudges
  • Beads panel or session launcher
  • Clicking a tile to focus its terminal window
  • Codex session monitoring (best-effort, verify during build)

Done when: With a real Claude Code session running on Mac, the dashboard shows a live tile for it with an updating token count, visible threshold markers on the gauge, MCP badges, and a spend estimate — all refreshing automatically without a page reload.

3

Alerts, Actions and Backlog

Adds the interaction layer: health alerts that nudge you when sessions need attention, a beads backlog sidebar with one-click session control, a session launcher that opens real terminal windows, and the Brain capture shortcut.

What gets built

  • Toast alerts when token thresholds cross (80K / 120K / 150K) with action label and Dismiss / Act buttons
  • Act button copies the relevant command to clipboard (e.g. "/compact", "/handoff")
  • Inactivity alert fires after 30 min (configurable) of no session activity
  • Per-tile audio toggle — on/off switch visible on each tile
  • Per-tile sound selector — choose from 4-6 distinct sounds in a curated library
  • Beads backlog sidebar — open items from bd list, grouped by project, with priority indicator
  • Beads item buttons: New Session (launcher modal pre-filled) and Load into Session (existing tile)
  • Session launcher modal — project selector, agent type, model, optional bead pre-load
  • Launcher opens a new iTerm2 (or fallback Terminal) window in the project directory
  • Clicking a tile focuses its terminal window
  • Brain capture button (persistent in header) opens modal with text field and Send action

Not in this milestone

  • Changelog feed
  • Brand config switcher UI
  • Creating or closing beads from the dashboard
  • Custom audio file uploads
  • Viewing past brain entries from the dashboard

Done when: A toast alert fires and plays a sound when a session crosses 80K tokens; clicking a beads item launches a new iTerm2 window in the correct project directory; the Brain capture button posts successfully to the Brain API and shows a confirmation.

  • Final ads-brand-audit pass with zero failures on ADS mode

Not in this milestone

  • Editing changelog content from the dashboard

  • Custom audio file uploads for alert sounds
  • Cloud distribution or packaging as installable product

Done when: The changelog panel shows recent session entries for a configured project and expands on click; switching to Generic brand mode applies a clean, professional design immediately; switching to Custom mode and pointing at a different token CSS file updates the UI without a restart. ads-brand-audit passes zero failures on ADS mode.
